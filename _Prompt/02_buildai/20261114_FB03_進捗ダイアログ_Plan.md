## らいおの言葉（逐語）

> ちょっとイメージと違ったな。プログレスバーの動き自体はいいんだけれども、この追加したプログレスの欄は、コンバート中にダイアログで出る感じがいい
> で、ロード中のGIF画像はその時にダイアログの余白の右側に出る感じね。
> 一応固まった時のためにキャンセルボタンも用意してもらって、ダイアログのレイアウトは一般的なWindowsのダイアログのレイアウトの感じで作ってほしい。
> タイトルは変換中を示す英語の名前でいいと思います。

## 実物での裏取り（HEAD の状態）

- メイン窓に `Progress` 欄（`gui._build_convert_tab`）と、右上に `busy_animation.BusyAnimation(root)`（`MbdGui.__init__`）がある。進みの通知は `JobRunner` が主スレッドの `_on_progress` へ運び、そこで欄のバーを更新する。
- Cancel の口が無い: `convert_one` は `progress(step, frac)` を呼ぶだけで、止める手段が無い。止めるには、通知の口（`tick`）で旗を見る形が自然。公開（`final_dir.rename(stage / OLD_NAME)` -> `staged.rename(final_dir)`）は、`tick(7, 0.0)` の後ろにある。
- 一発変換の `convert_unconverted` は、最後に起点（`scan_started_at_ns`）を進める。止めたときに進めると、やめた物が次から「起点より古い」として候補に出なくなる（FB01 の判定表 `OLDER`）。

## 作るもの（How）

| 項目 | 中身 |
|---|---|
| `mbd2mes/progress_dialog.py`（新規） | モーダルの `tk.Toplevel`。タイトル `Converting...`・固定サイズ・親窓の中央（親が見えなければ画面の中央）・`transient`（最小化/最大化なし）。上: `File k/n: 名前`・`Step k/7: 段名`。中: % 付きの determinate バー（戻らない）。下: `Elapsed: m:ss    Remaining: about m:ss`（始めのうちは `calculating...`）。区切り線。右下に `Cancel`（× と Esc も同じ）。右の余白に GIF（無ければ置かない = 余白を詰める） |
| 残りの目安（`progress.py`） | 経過時間 / 進み x 残りの進み。3 秒・3% に満たない間は出さない |
| Cancel の通し方 | `threading.Event` の旗。`JobRunner.cancel_event`・`Emitter.cancel`・`request_cancel`。ダイアログは旗を立てるだけ（`on_cancel`）。止まるのは、変換が次の通知の口で旗を見たとき |
| `convert.convert_one(cancel=…)` | `tick` で旗を見て `Cancelled(段名)` を投げる。作業フォルダは `finally` で消える・既存の MES・出力先・対応表は変わらない。`tick(7, 0.0)` の後に `publishing` を立て、**公開の最中は止めない**。公開の最中に旗が立っていたら、公開が終わってからログに出す（その 1 本は変換済みとして終わる） |
| `app_convert.convert_many(cancel=…)` | 始める前に旗を見る。`Cancelled` は失敗にも成功にも数えず、残りを始めない。ログ: `[CANCEL] <名前>: cancelled while "<段名>"; nothing was written for it` / `The remaining n file(s) were not started: …` / `Finished before the cancel: …` |
| `batch.convert_unconverted(cancel=…)` | 残りをやめる。止めた 1 本は台帳に載せない。**起点は動かさない**。止めた物・始めなかった物は一覧に残す（もう一度押せる）。ログ: `[CANCEL] Batch conversion cancelled. Finished (kept as converted): …; Stopped in the middle (nothing written): …; Not started: …` |
| `jobs.py` | **仕事の間は GC を止め、終わったら主スレッドで `gc.collect()`**（別スレッドの GC が主スレッドの Tk の変数・画像を片付けて Tcl が落ちるのを防ぐ。全件の試験で実際に `0x80000003` で落ちた） |
| `gui.py` | Progress 欄・窓の端の GIF・経過時間の更新を削除（メイン窓は FB02 以前の見た目。ログ欄は残る）。`_start_job(dialog=True)` で変換の本体だけダイアログを出す（走査は出さない）。終わったら（失敗でも）ダイアログを閉じてから部品を戻す。ダイアログが出せなくても変換は続ける |
| `busy_animation.py` | `attach`（置き方を呼び出し側が決める）・`release`（閉じるとき、コマを主スレッドで手放す） |
| `tools/render_dialog_snapshot.py`（新規） | ダイアログを画面の外に置いて PrintWindow で PNG に撮る（窓を利用者の目に出さずに見た目を確かめる） |

## 試験の計画

- Cancel の各場面（読み取り中・値の展開・定義作り・書き出し中・ラップと検査・公開の直前・公開の最中・一発変換の 2 本目・既存の MES の上書きの途中）で、出力先・既存の MES・対応表・台帳・起点が壊れない。**期待値は、変換前の出力先の写し（ファイルごとの SHA-256）・同じ入力を別の出力先へ素で変換した MES・手で組んだ台帳/起点の状態**から作る
- ダイアログ: 形（タイトル・固定サイズ・位置・右下の Cancel・バー・経過時間）・Cancel のボタン/×/Esc・自動で閉じる・失敗でも閉じる・GIF の有無（有: 右の余白で動く / 無: 余白を詰める）・メイン窓に Progress 欄と窓の端の GIF が無い・CLI は変わらない
- mutation、既存の試験は通ったまま（FB02 の試験のうち、外した Progress 欄・窓の端の GIF に結び付いた物だけダイアログ版へ書き直す）
