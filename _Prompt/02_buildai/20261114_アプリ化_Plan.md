## 3. 実装前の 4 問（rumination）

- **Q1 根治か**: 対応表を「写す」だけでは entry 数のずれで落ちる（§2-1）。症状隠し（行数の検査を外す）ではなく、entry と元の計画の対応を記録（`calls`）から作り直す。保護する行も、画面で禁止するだけでなく**変換の側で無視して警告**する（対応表のファイルを手で書き換えられても守れる）
- **Q2 最上位命題に近づくか**: らいおが Analyzer で変換後の MES（地図つき）を正しく見られること。対応表は既定（恒等）のとき**今と同じ MES を 1 byte も変えない**こと（T-I1）を最優先の不変条件にした。変えるのは、利用者が表を編集した行だけ
- **Q3 バグの芽の先送り**: (a) 任意名が cp1252 で書けないとき entry が減る → RCZ2MES の `_name_encodable` 相当で layout から外す。(b) 倍率 0・NaN・null → `validate_scaling_factors` が例外にする（写し）。(c) 倍率を掛けて 16 bit の範囲を使い切る/超える → `make_entry` が gain/offset を値から決める（`ddd_generator`）ので溢れない。値が全部同じなら退化する件を T で確かめる。(d) 対応表の自動成長が保存できない → 変換は続け、`map_saved=False` を返して GUI に警告（写し）。(e) 対応表の同時書き込み（GUI と D&D）→ `merge_and_save_map` は読み直して未登録行だけ足す（写し）
- **Q4 間違っていたら最初に何が壊れるか**: `convert.py` の `layout`（記録ファイルの行）がずれ、記録の列と実際の MES のチャンネルが食い違う。→ T-R1 で「記録ファイルの全行 = DDD の entry」を別経路（`mes_reader.parse_ddd`）と突き合わせる。次に壊れるのは地図（V_GPS の改名）→ T-M3

### 5-2 対応表が効くことの確かめ（受け入れ条件 1・2）

合成 MBD（`synth_mbd.py`。生値を自分で決める）で、**期待値は手計算**:
- THP（生値 500、A/B = 1000/10000 → 物理量 50.0 %）に Multiplier = 2・Offset = 1・単位 `x` → MES の値 101.0（誤差は 16 bit の量子化の半分以内）、単位 `x`。`test_multiplier_offset_applied_hand_computed`
- 任意名 `Throttle` → 元の `THP` も `Throttle` も MES にあり、2 本の値が一致。`test_custom_name_adds_a_copy`
- 任意名が cp1252 で書けない（`スロットル`）→ コピーだけ書かれず警告が出て、元は書かれる。変換は成功。`test_unencodable_custom_name_skips_copy_only`
- 任意名が既存名と衝突（`Ne` → `SysV`）→ `unique_names` の規則で一意化され、全 entry の名前が一意。`test_custom_name_collision_is_made_unique`
- 倍率 0・null・NaN → `ValueError`（変換前に止まり、出力先に何も作らない）。`test_bad_scaling_stops_before_writing`
- 単位を指定せず倍率だけ → 写しの整合性ガードで停止（`apply_channel_map`）。GUI でも同じ検査で OK が押せない（T-G）
- **`layout` の意味の正しさ（Codex [4] 反映・§2-1 の本命の試験）** `test_layout_maps_each_entry_to_its_source_row`: レート（200 Hz・25 Hz）・値・先頭の保持（lead）が互いに違う 3 本以上の合成チャンネルを、**任意名のコピー・cp1252 で書けない任意名・既存名との衝突・32 byte を超える任意名**と同居させて変換する。`mes_reader.parse_ddd`（別経路）と `.A??` の読み戻しで、各 entry の**値列・divisor・名前を、試験が独立に保持した元の行の期待列（手で作った生値 → 手計算の物理量）と照合**し、記録ファイルの各行（名前・レート・標本数・source・lead）も同じ期待列と照合する。件数の一致だけを合格条件にしない
- 記録ファイルの全行が DDD の entry と 1:1（上の試験に含める）
- 実データ（`MBD2MES_SAMPLE` があるとき）: 表を編集して 1 本変換 → 全チャンネルの標本数が `ceil(T×レート/1000)`（今の `test_sample_every_channel_covers_the_duration` を表つきでも通す）

### 5-3 試験を試験する（mutation）

実装後、次を 1 つずつ壊して**該当の試験が落ちる**ことを確かめ、戻して緑にする（`mutation-verified-test`）。復元は `.bak` ではなく変異前の内容を一時ファイルへ退避して戻す（他レーンの作業ツリー共有のため、変異中は 1 回の実行で戻す）。
M1 `layout` の対応を元の `zip` に戻す（および layout の 2 行を入れ替える）→ **`test_layout_maps_each_entry_to_its_source_row` が値・divisor・記録の照合で落ちる**ことを合格条件にする（変換が例外で失敗しただけでは合格にしない）/ M2 `is_protected` を常に False → T-protected が落ちる / M3 `make_scaling_fn` を常に (1,0) → T-mult が落ちる / M4 `merge_and_save_map` を上書き型に → T-auto-grow が落ちる / M5 `map_path` が書込検査をしない → T-fallback が落ちる / M6 `-o` 省略の既定を外す → T-cli-config が落ちる。
さらに**新しい試験は直す前のコードで落ちる**ことを、`git stash` 等の git の状態変更でなく、**変更前の `convert.py` の `.bak` を一時フォルダで差し替える**形で確かめる（git は使わない）。

### 5-4 GUI の試験と away-gate

- ロジック（表の行の並び・フィルタ・編集ダイアログの検査・保存の呼び出し）は Tk を使わない関数に分け、通常の試験で通す。`test_gui_logic.py`
- Tk の部品（`Tk()` を作る）は、**窓を出さない**（`root.withdraw()`・`update_idletasks()` だけ）smoke を 1 本。Tk が使えない環境では skip。利用者の画面に窓は現れない
- 実 exe を起動して窓が出ることを確かめるのは、**skill `away-gate` の行列・貸出に従う**（実装時にスキルを読んで従う）。起動後は窓を自動で閉じる（`--version-file`・`--selftest` ではなく、**窓が出るまで待って標題を取って終了**する手段は §9 の試験 T-exe2）

## 6. 対応表の初期値

- **キー**: MES に書く側の名前（`ChannelPlan.name`。例 `Ne`・`THP`・`THGRPADJ`・`V_GPS`・`Latitude`）。`GPSspd` は書かない（GPS ブロックの速度と同値で V_GPS として書く。`channels.py:68`）ので載せない
- **行の中身**（写した形のまま）: `unit: null`（= MBD の単位に従う。`unit` を埋めない理由は、倍率が 1 なら元の単位のままが正しく、埋めると「利用者が決めた単位」と区別できなくなるから）・`custom_name: null`・`raw_unit`（MBD の単位。参照用の表示）・`multiplier: 1.0`・`offset: 0.0`
- **どの行を入れるか**: 標本（実データ）を `plan_channels` に通して書かれる名前を全部。記録の無いチャネルは入れない（`no value records`）。`tools\make_channel_map_seed.py` が `MBD2MES_SAMPLE` の標本から**一度だけ**作り、生成した `channel_map.seed.json` を**追跡する**（Codex [7]。clone・ビルドでは再生成しない）。生成時の入力の SHA-256・コマンド・行数を `docs\provenance.md` に記録する
- **seed の正当性の確かめ（Codex [7][9] 反映・サンプルが無い環境でも通る）**: `test_seed_rows_match_appendix_a` は**文書整合性の試験**として分離する。出どころは別（付録 A は、参照実装 `mbd_dump.py` による以前の解析の記録で、`plan_channels` を通っていない。件数の列あり）。付録 A の件数 > 0 の行から `GPSspd`・GPS1・GPS2 を除いた名前の集合が、追跡した seed のチャンネル名の集合（保護 3 行を除く）と一致すること。追跡する 2 つのファイルだけで通る。`MBD2MES_SAMPLE` があるときは、加えて `test_seed_equals_plan_channels_of_sample`（標本を通した結果と seed が一致）を回す
- **名前と単位を「読みやすく」する件**: 発注書の動機（`THGRPADJ` を 2D で読みやすく）は、**使う人が表で任意名を足す**形で満たす。**初期値は恒等**にする。理由: (1) 意味の確証があるのは換算が確かめられた一部だけ（`mbd_format.md` §6。THGRPADJ は未解明）、(2) 任意名は「元を残して別名を足す」ので、初期値で名前を足すとチャンネル数が倍になり 2D の一覧が長くなる、(3) 頼まれていない先回りは避ける（CLAUDE.md）。**ただし GUI の表に、意味の補助として「Description」列（読むだけ）を足すかを §11 の問 2 にした**（既定: 足さない）
- **版を上げても消えない**: 利用者の表は exe の隣の `channel_map.json`。seed は exe の中（`_MEIPASS`）。新しい版の seed に行が増えても、既存の表は上書きせず、**変換時の自動成長で足りない行だけ足す**。seed の行を「初期化（Reset Row）」で戻すときだけ seed を読む（写し）
- 保護する行は表に載せるが、編集・初期化・削除ができない（`FIXED_MESSAGE`）

## 7. 変換の中身（`convert.py` の改修の詳細）

1. `plan_channels` の結果から、書く行（`narrow_rows`）を今までどおり作る。ここで V_GPS も行に入る（保護名として恒等で通す）
2. 順序（Codex [8] 反映）: **対応表の検証（倍率・オフセットの不正、単位の整合性ガード）は、出力先の既存確認・`out_dir.mkdir`・作業フォルダ作成・設定ファイルへの保存よりすべて前**に終える（今の `build_entries` の呼び出しが `convert.py:263` の `mkdir` より前にあることを保つ）。自動成長の**保存は、MES を公開し終えた後**（失敗した変換は設定にも何も残さない）
3. `layout`（Codex [3] 反映）: `ddd_generator` を改変せず、規則を二重に持たない作り方にする。`make_apply_fn` が返す候補の列を、**写した `dg.sanitize_name` 本体**で調べて cp1252 で書けない候補をあらかじめ取り除いた列にして `build_entries` へ渡す（元の候補 `i = 0` は `dg.sanitize_name(raw_name)`、任意名は `dg.sanitize_name(candidate)` — `build_entries` が使う判定と同じ関数）。取り除いた分は `skipped` に理由つきで記録。こうして**`build_entries` へ渡した候補列がそのまま `layout`**になる（行 → 候補 → entry の順序は `build_entries` の `pending` の順 = `records` の順 × 候補の順）。最終の名前（32 byte 切り詰め・衝突の `~2` など）は `entries[k].name` から取るので、規則を再実装しない。保険として `len(layout) != len(entries)`、および各 entry の `divisor`・値列が行のレートと値に一致することを `ConvertError` で確かめる（黙って続けない）
4. Lat/Lon は今までどおり `make_wide_entry`（表を通さない）
5. 記録ファイル: **表が実際に効いた行があるときだけ**（改名・倍率・単位の上書き・任意名のコピー・保護の警告）、`Channel map: applied` とその行の説明（`renamed`・`scaled`・`copy of`）を足す。**表が恒等のときは記録ファイルも今と 1 byte も変えない**（Codex [1] 反映。T-I1 の範囲は出力フォルダの全ファイル）
6. 自動成長（公開の後）: 計画に出た全部の名前（書かなかったものも）を `grow_with_defaults` で表へ足し、足したときだけ `merge_and_save_map`。保存できなければ `map_saved=False`（変換は成功のまま）

### 7-1 対応表ファイルが壊れていたとき（Codex [6] 反映・状態を決める）

### 7-2 同時に書く（Codex [5] への対応: 一部採用）

- 起こること: GUI の保存と、別プロセス（D&D・CLI）の自動成長が重なると、後に書いた側が勝つ。**失われうるのは「自動成長で足された行」だけ**で、次の変換で同じ初期値の行が再び足される（自己修復）。GUI の利用者の編集は自動成長が消せない（`merge_and_save_map` は未登録行しか足さない）。自動成長どうしの競合も同じく自己修復
- 採用する安全策: GUI の保存は「ディスクを読み直し、**GUI がまだ見ていない行（ディスクにあって GUI のメモリに無く、この窓で削除もしていない行）を保ってから**全体を書く」。これで GUI が古いメモリで他プロセスが足した行を消す窓を小さくする。排他ロックは入れない（ロックの残骸・Windows での扱いの複雑さのほうが、自己修復する損失より重い。`critical/high` の指摘への棄却部分なので §11 問 4 で承認者の裁定を求める）
- 試験: `test_gui_save_keeps_rows_added_by_another_process`（足された行が保たれる）・`test_gui_save_deletes_only_rows_deleted_in_this_session`・`test_lost_autogrow_row_is_readded_next_convert`（競合の後始末を決定的に再現: 古いメモリの表を保存 → 次の変換で行が戻る）。競合そのものの barrier 試験は置かない（決定的に再現できる形に落とした試験で足りる）

乗数・オフセットは**MBD の換算の後の物理量にかかる**（`値 × M + O`。`build_entries` の既存の意味）。THGRPADJ のような未解明の換算は、生値に利用者の M・O がかかる。この意味を GUI の列見出しの横に 1 行で出す（`Multiplier / Offset (applied after the MBD conversion)`）。

## 11. 承認者に決めてほしいこと（4 件。推奨つき）

1. **版**: `0.1.0` を `0.2.0`（使える形の最初）にしてよいか。推奨: Yes。理由: RCZ2MES の `0.3.0` と同じ位置づけ（M1 の CLI を 0.1.0 とみなし、GUI つきの最初を次へ）。`--version` の形が `MBD2MES v0.2.0 (abc1234, built …)` へ変わる（試験に依存なし）
2. **表に読むだけの「Description」列（MBD のチャネルの意味の補助。例 `GYROAN` = バンク角）を足すか**。推奨: 足さない（頼まれていない・意味は一部だけ確実。足すなら別の発注）。足す場合、確度つきの辞書を `docs\mbd_format.md` §6 から作る（約 40 行、半日未満）
3. **`CLAUDE.md` の「環境」節に、GUI・exe の確定した構成（パッケージ構成・設定の置き場・ビルド手順）を追記する**のは、実装後の報告書で提案する形でよいか。推奨: Yes（私は `CLAUDE.md` を直接書き換えない）

### 16-3 FB01-3: Browse と Change が連動して見える原因

- **原因（コードから特定。画面では未確認の推定）**: Change が `filedialog.askdirectory()` に `initialdir` を渡していなかった。Browse も、設定に前回のフォルダが無い初回は `initialdir=None`（Tk へ送られない）。Windows の共通ダイアログは、`initialdir` が無いと「このアプリで前に使ったフォルダ」を覚えていて、どちらの画面もそこから始まる。Browse で選んだフォルダが次の Change の始まりになり、その逆も起きる。これが「両方連動しているような動き」。
- 直し: LD2MES の Ld2Mes-016 と同じく、Browse は「前に .MBD を選んだフォルダ」、Change は「今の出力先」を `initialdir` に渡す（設定が無い・もう無い・読めないときだけ None）。
- 試験: 2 つのダイアログの `initialdir` が別々の設定から来て、一方の変更が他方へ移らない（`test_browse_and_change_start_from_different_settings`）。mutation で、Change から `initialdir` を外す・Browse が出力先を見る、の 2 通りを壊して落ちることを確認。

### 16-4 FB01-4: HED の日付（調査結果と案。**親の裁定待ち。この項は実装していない**）

- 実測（標本の `.MBD`・SHA-256 照合済みのコピーに対して `scratch/scan_date.py`。読むだけ）:
  - ヘッダ 0x000〜0x1FF とチャネル表・GPS ブロックに**日付は無い**（0x2000 未満の非ゼロ領域を全部列挙。GPS の UTC は時刻だけ）。`docs/mbd_format.md` §2 の記述（[実測]）を、今回も独立に確かめて同じ結論。
  - 日付の符号化候補 18 種（ASCII の `2026`・`20261108`・`261108`・`26.11.8`、BCD、2 進、uint16 の 2026、DOS 日付、2026-11 の Unix 時刻の範囲）を、ヘッダ領域とファイル全体（14.6 MB）で全探索: ヘッダ領域は 0 件。ファイル全体で当たったのは BCD の `08 11 26` の 1 件だけ（3 byte の並びが 14.6 MB に偶然 1 回現れる程度の件数。ヘッダではなくデータの中。意味は無いと判断）。
  - 原本のファイルの時刻は 2026-11-13 19:08（ダウンロードした日）。コピーは 22:10。**ファイルの更新時刻は、レースの日（2026-11-08）ではなく、受け取った日**。今の仕組み（更新時刻に最も近い日を選ぶ）が `13.11.2026` を出したのはこのため。
  - 提供者の付けたファイル名は `26.11.8…`（年 2 桁・月・日）で、**レースの日が入っている**。フォルダ名 `1106_Sz.26` は 2D のイベント名（イベントは 11/06〜、レースは 11/08）で、日付の代わりにはならない。MBDA2 が付ける元のファイル名は `月日時分.MBD`（説明書の記述。年は無い）[推定: `docs/mbd_format.md` §2 の引用。説明書の実物は今回見ていない]。
- 影響: HED の日付表示（Analyzer のセッションの日付）だけ。チャンネルの値・時刻軸・ラップには影響しない。
- 案（どれも小さい。`batch.convert_unconverted` の `date_for` は既に用意した）:

| 案 | 中身 | 良い点 | 悪い点 |
|---|---|---|---|
| A | GUI に日付の欄（YYYY-MM-DD）を置く。変換の一覧すべてに 1 つの日付 | 明示的で分かりやすい。CLI の `--date` と同じ | 一発変換で日がまたがる複数本に使えない。空にすると今と同じ誤りが出る |
| B | ファイル名から日付を読む（`yy.m.d`・`yy.mm.dd`・`yyyy-mm-dd`・`yyyymmdd`・`yymmdd`、MBDA2 の `MMDDHHMM`〔年は更新時刻から〕）。読めなければ更新時刻 | 1 本ずつ自動。一発変換でも効く | 名前の約束に依存する（年月日の順の取り違え・名前に日付が無いファイル） |
| C（推奨） | B を既定にし、A の欄（空 = 自動）で上書きできる。確認の画面と記録に、1 本ごとに「日付とその出どころ（ファイル名 / 欄 / 更新時刻）」を出し、**更新時刻にしか頼れないときは印を付けて警告** | 自動で正しくなる場合が多く、外れても直せる・見える | 実装が A・B より少し多い（名前の読み取りの関数 1 つと欄 1 つ。試験は名前の型の表） |
| D（棄却） | 出力先の 2D のイベントフォルダ名（`1106_SUZUKA.26`）から読む | — | イベントは複数日。レースの日と違う（上の実測） |

- 推奨 C の試験の案: 名前の型の表（`26.11.8鈴鹿…` → 2026-11-08、`26.11.08`、`2026-11-08`、`20261108`、日付無し → 更新時刻 + 警告、年またぎ・不正な月日 → 更新時刻 + 警告）。期待値は表に手で書く。

承認者の裁定（FB01）:

1. **一発変換の初回の動きは LD2MES に揃える**（起点が無く「全部変換」オフの初回は、起点だけ記録して変換しない）。実装: `gui._on_convert_unconverted`（参照実装と同じく GUI 側）。画面は LD2MES の文言（`MBD2MES - Checkpoint Recorded`・`Baseline checkpoint recorded for this directory.` … `.ld` は `.MBD` に）、ログにも `Baseline checkpoint recorded for <フォルダ>. 2. **HED の日付は案 C**: `mbd2mes/dates.py`。
   - 優先: 明示の指定（CLI の `--date`・GUI の日付の欄。空 = 自動。全部の入力に使う）> ファイル名 > 更新時刻（警告）

   - 確認の画面（`Recording date (HED) and where it comes from:`）とログ（`[INFO] <名前>: recording date 2026-11-08 (file name)`）に、1 本ごとの日付と出どころを出す。更新時刻に頼る物は `from the file modification time -- CHECK` と `WARNING: n file(s) have no date in the name …`。変換の結果・記録ファイルにも警告（`convert_one` が `date=None` のとき必ず警告）と、日付の出どころ（`date source: file name 2026-11-08 (local) + GPS time of day`）が残る
   - CLI の `--date` は今までどおり最優先。`--date` が無いときは名前から 1 本ずつ（従来は更新時刻だけだった）
