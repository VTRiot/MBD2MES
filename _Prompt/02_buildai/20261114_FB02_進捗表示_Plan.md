## らいおの言葉（逐語）

> この MBD からの変換のツールだけ少し処理に時間がかかっているように思うのね。その間、ユーザーはボタンを押したあと固まっているのかどうか判断できないから、例えばローディング中のくるくるを出すとか、できれば変換におけるプログレスバーをステップ毎に出して「今何分の何の処理をしてます」とプログレスバーで進んでいる様子を何パーセントで見せるとか、そういうアクションがあってもいいかなと思った。

## 実物での裏取り（HEAD の状態）

- **今は固まる**: `gui._on_convert`・`_on_convert_unconverted` は主スレッドで `convert_many` を同期に呼ぶ（`gui.py` の変換の節）。変換中は Tk の主ループが止まり、窓が応答しない。
- 変換の段: `convert.convert_one` は 1 本の関数で、段の境目に通知の口が無い。写した `mes_writer.write_reconstructed_mes` は不透明だが、`values_by_name[名前]` を entry ごとに 1 回引く（`mes_writer.py:335-338`）ので、写しを改変せずに、書き出しの中の進みを数えられる。`ddd_generator.build_entries` は `reader.read_channel` をチャンネルごとに呼ぶ。
- 読み取り `mbd_reader.read_mbd` のデータ領域の走査は 1 レコードずつの Python のループ（標本で約 500 万レコード）で、最も重いと見込んだ。

## 作るもの（How）

| 項目 | 中身 |
|---|---|
| `mbd2mes/progress.py`（新規） | 7 段の名前と重み・段の中の進み → 全体の %（File k/n つき）・画面へ渡す出来事（`ProgressEvent`）。tk を使わない |
| `convert.convert_one(progress=None)` | 段の境目と、重い段の中（読み取り 1% ごと・値の展開は 1 チャンネルごと・定義作りは 1 チャンネルごと・書き出しは 1 チャンネル書くたび）で `progress(step, frac)` を呼ぶ。結果は変わらない。CLI は渡さないので出力は変わらない |
| `mbd_reader.read_mbd(progress=None)` | データ領域の走査の進みを 1% ごとに知らせる |
| `app_convert.convert_many(progress=...)`・`batch.convert_unconverted(progress=...)` | 段の進みを全体の % にして渡す。失敗・見送りの 1 本も「終わった」印で全体を進める |
| `mbd2mes/jobs.py`（新規） | 変換を別スレッドで回し、進み・ログ・結果を `queue` で主スレッドへ運び、`root.after` で読む。tk を使わない |
| `gui.py` | Progress 欄（`File k/n`・`Step k/7: …`・全体の %・不定のバー・経過時間）。変換中は変換・一発変換・一覧・出力先・日付・対応表の部品を押せなくし、終わったら（失敗しても）元の状態へ戻す。走査（一発変換）も別スレッド。変換中に窓を閉じるときは確認 |
| `mbd2mes/busy_animation.py`（新規） | 窓の右上の端に置く GIF（約 1.5 cm・透過 1 色・数コマ）。変換中だけ再生し、終わったら止める。置き場は `GIF_RELATIVE_PATH`（`Pic/anim/busy.gif`）の 1 か所と、環境変数 `MBD2MES_BUSY_GIF`。無い・壊れているときは何も出さず動く。spec は GIF があれば `busy.gif` として同梱 |
| `tools/measure_steps.py`（新規） | 標本で各段の時間を測る（重みの根拠） |

## 段の数と重み（実測で決める）

7 段: 1 読み取り / 2 値の展開 / 3 GPS / 4 定義作り / 5 書き出し / 6 ラップと検査 / 7 仕上げ。重みは `tools/measure_steps.py` の実測（標本 14.6 MB・3 回の中央値）の比で決めた（実測値と最終の重みは報告書）。

## 試験の計画

- 進み具合の通知: 段の順・単調に増える・最初 (1, 0.0)・最後 (7, 1.0)・重い段は段の中でも進む・結果は変わらない（記録ファイルを含め 1 byte も違わない）・失敗では 100% を出さない・複数本の File k/n と、失敗/見送りの 1 本でも全体が進んで 1.0 で終わる・CLI の出力に進み具合が出ない
- GUI: 変換中に主ループの `after` が動く（固まらない）・部品が押せない・終わったら元へ戻る（最初から灰色の物は灰色のまま）・失敗で戻る・一発変換の走査と変換も別スレッド・チェックが戻る・バーは戻らない・% が止まる間も不定のバーと経過時間が動く・変換中は対応表の操作が効かない・窓を閉じる確認
- GIF: 無い・壊れているときに落ちない・変換中だけ再生して止まる（手で組んだ 3 コマの透過 GIF）・窓の右上・差し替え口
- mutation（実装では 23 種）、既存の試験は通ったまま
