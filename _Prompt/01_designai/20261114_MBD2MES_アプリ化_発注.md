## What

1. GUI（tkinter）を作る。少なくとも次の 2 つ
   - 変換: `.MBD` を選び（複数可）、出力先を選び、変換する。結果とログを画面に出す
   - 対応表（Channel Map）: MBD のチャネルごとに、MES での名前・単位・一次変換（Multiplier・Offset）を編集して保存する。変換はこの表を使う
2. 対応表は exe の隣に保存し、版を上げても消えない（LD2MES・RCZ2MES と同じ置き方。書けないときの退避先も同じ）
3. PyInstaller の単体 exe を作る手順（スクリプト）。アイコンは後で支給されるので、`ICON\MBD2MES.ico` があれば使い、無ければ既定のまま作れる形にする
4. 今の CLI はそのまま使えること（GUI と同じ変換の関数を通す）

## 作らないもの

- GPS のマージ（RaceChrono の `.rcz` を足す機能。LD2MES の `gps_merge.py`・`gps_sync.py`）
- ラップを切る機能（LD2MES の `course_laps.py`・コースの区間で切る系）
  - 親の解釈: MBD 自身が記録したラップ（ヘッダのコントロールラインと記録の印から今 `.IXR` に書いているもの）は「切る機能」ではないので残す。違えば親が直す
- 派生チャンネル（変換表で信号を復元する機能）・Fix・設定の履歴・マニュアル。らいおに要否を聞いている。答えが来るまでは作らない

## Why

- らいおは LD2MES・RCZ2MES を同じ手つきで使っている。揃えれば覚え直しが要らない
- MBD のチャネル名は短い略号（例: `THGRPADJ`）で、2D で読みやすい名前と単位に替えたい。換算の未解明分（`docs\mbd_format.md` の未解明の節）を、使う人が一次変換で補える

## 受け入れ条件

| 条件 | 判定方法 | 証跡の形 |
|---|---|---|
| 対応表の名前・単位・一次変換が MES に反映される | 試験: 表を変えて変換し、MES の名前・単位・値を、表とは別の出どころ（手計算の値）と比べる | 試験の名前と結果 |
| 対応表が exe の隣に保存され、再起動で戻る | 試験（保存→読み直し） | 試験の名前と結果 |
| CLI が今までどおり動く | 既存の試験が全部通る＋実データで 1 本変換 | 試験の結果・出力の一覧 |
| exe が作れて起動する | ビルドスクリプトを回し、exe を起動して画面が出ることを確かめる（away-gate） | ビルドのログ・exe のパス |
| 完了 | らいおが exe で変換した MES を 2D Analyzer で開いて見る | 親がらいおから受け取る（あなたの範囲外） |
