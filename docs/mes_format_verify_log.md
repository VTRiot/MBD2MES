## 検算結果（原文）

出典を開いて確かめた。確認できた主張は多数で、以下は誤り、確度の過大、出典の不備のみ列挙する。

**A. 誤り・出典のずれ（修正した）**

1. 記録ファイルの行番号が誤り。`rcz2mes.py:675` は `_build_record` 呼び出しで、書き込みは `:677`、定数 `RECORD_NAME` は `:53`、docstring は `:14`。根拠 `C:/_Prog/ECU/Logger/RCZ2MES/rcz2mes.py`
2. 実データ F5 の節 ID の書き方が誤解を招く。F5 は `[300]` から始まる 156 節で、`[340]`〜`[35E]` は一部にすぎない。ID と `6=` 第6・拡張子は単純に対応しない（例 `[340]`＝A41・第6 `41`、`[35C]`＝C05・第6 `5D`）。根拠 `C:/RaceData/01_02M/25/0406-2_SuzukaTwin.25/F5-02M-01.MES/F5-02M-01.DDD`
3. `4=` の表の「"説明"」が誤り。生成側は第5欄を引用符つき DEL で書く（`ddd_generator.py:223-228`）。実データの第5欄は `"GPS speed"` や `""` など。
4. 不変量チェックの `1=` 第1 の記述が不正確。実装は「`"4"` と一致」かつ「10000 未満」を検査する（`ddd_invariants.py:22,86-96`）。
5. X1 の行番号が誤り。DDD の cp1252 読みは `ddd_invariants.py:49`（`:44` は分割関数の末尾）。
6. X1 が `mes-format.md` の表を「cp1252・strict」と書いたが、表は「cp1252・CRLF」で strict の記載はない（`research_raw/mes-format.md:26`）。strict はコード側（`mes_writer.py:_ENCODING` と `errors="strict"`）にある。
7. 013 の行番号と範囲が誤り。受理を確認した記述は `Ld2Mes_013_owner_check.md` の 90〜98 行で、64〜66 行は計画表。確認できたのは P4（`_DN`）だけで、P1・P2・P3・P5〜P7 は未実施（98 行）。

**C. 追記した事実（反証で出たもの）**

- F4 の IXR 末尾を int32 の語で読むと `[(8<<16)|80, 7088, 0xFFFF0008, 337<<16]`。書き出し側は 2 語目に MainSamplingRate、3 語目に N を置くが、実データの 3 語目は上位 16 bit が −1、4 語目は 337<<16 で、2 語目も 7088 になる。根拠 `mes-format.md:73`
- `ddd_generator.py` は LD2MES 版と、改行（CRLF/LF）を除いて同一。`mes_writer.py` はバイト同一。`ddd_invariants.py`・`mes_reader.py` は diff -q で差分なし。`lap_files.py` は冒頭の docstring が異なり、LD2MES 版は書き出し関数を持たない。
