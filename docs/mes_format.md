## 1. MES フォルダの構成・命名

- MES の実体はフォルダ `<名前>.MES/`。中に `<名前>.DDD`・`<名前>.<A??|C??>`（1 チャネル 1 ファイル）・`<名前>.CAL`・`<名前>.HED` ほか [実測]（ハブ §2・§3、2007 年資料 §1）。実データ F4 には `.IXR`・`.LAP`・`.STI` もある [実測]
- RCZ2MES が書くのは DDD・A??・CAL（0 byte）・HED・IXR・STI と、独自の記録ファイル `RCZ2MES_record.txt`（`RCZ2MES/rcz2mes.py:14,53,677`）。記録ファイルが入った MES を Analyzer で開けた [推定]（M2 以降の exe 出力は常に記録ファイルを書くことからの推定。記録ファイルの有無だけを比べた実験は無い）
- CAL は空ファイル（`RCZ2MES/mes_writer.py:121-123`）。2D 純正 Demo-CAR.CAL も 0 byte [実測]（`HA22S_M130_hed_format_decode.md` §1.5）。2D が CAL を書き換えるかは [未確認]（f6 調査 U1）
- 名前: ロガーが付ける名前はテンプレート（LONGDATE・MEASLONGDATE・DATE・TIME・MEASTIME・`________`＝ロガー名・`********`＝シリアル・`##`＝計測番号）で決まる（`MES命名規則.txt`）[実測]。変換ソフトの名前は自由。RCZ2MES は `[A-Za-z0-9-]` 以外を `-` にして連続を畳み前後の `-` を除く（`RCZ2MES/rcz2mes.py:353-356`）。49 文字の名前の MES が開けた [受理]（M1 確認 5 章）。長い名前の上限は [未確認]
- 親フォルダ（イベント）: `Event.ini`・`Users.ini` が要る。試験は `C:/RaceData/LD2MES_PoC/` の `Event.ini` 等の写しを置いた（M1 5-2・M2 確認書）。無い場合に開けるかは [未確認]（Analyzer が作るという観察はハブ §3）
- 書き出しの手順（RCZ2MES・[受理]）: 出力先の中に作業フォルダを作る→DDD・データ・CAL・HED・IXR・STI・記録ファイルを全部書く→不変量チェック→違反なしなら `.MES` へ rename。途中失敗でも既存の MES は消えず、壊れた MES を置かない（`RCZ2MES/rcz2mes.py:649-705`）

## 2. DDD（チャネル定義）

### 2-1. ファイルの書式

- INI 形式のテキスト。節 `[hex]` が 1 チャネル。値はカンマ区切り、ダブルクォートの中のカンマは区切りでない（`ddd_invariants.py:24-43`）
- 書くときは cp1252・strict・CRLF、各節の後に空行 1 行、ファイル末尾も CRLF（`mes_writer.py:45,98-118,261-290`）。この書式で Analyzer が開けた [受理]。外形がバイト一致しないと差分になる事実は 09-04 の実機確認レビューで判明（同 :85-88 のコメント）[推定: 実機で何が起きたかの記録は未精読]
- 読むときは latin-1（ハブ §2: cp1252 だと未定義バイトで落ちる実データがある）。ハブと書き出し側の食い違い扱いは part2 §9
- 空欄は 0x7F（DEL）1 文字で書く。`4=` の第 5 欄は引用符つき DEL、第 7 欄は素の DEL（`ddd_generator.py:82-85,223-228`。実データ全数一致という出所コメント [推定]）
- 節 ID: 16 進・先頭ゼロなし・大文字。RCZ2MES/LD2MES は `0x300 + (通し番号-1)`（`ddd_generator.py:392`）[受理]。実データの F5 も `[300]` から始まる 156 節だが、ID と拡張子・`6=` 第6 の対応は単純でない（例 `[340]`＝A41・第6 `41`、`[35C]`＝C05・第6 `5D`）[実測]。ID の意味は [未確認]
- 通し番号 1〜N の拡張子: `A` + 36 進 2 文字（A01…A0Z…AZZ。上限 1295）（`ddd_generator.py:247-255`）[受理]。実データには C?? も A0H のような英字入りもある [実測]（F5 の拡張子一覧）。C?? は計算チャネルの印（ハブ §1・推定）

### 2-3. 数値の書式・レート

- gain・offset の 16 進: 大エンディアン IEEE754 float32 を 16 進にして大文字、先頭の 0 を詰める。0.0 は `00000000` でなく `0`（`mes_writer.py:176-190`）。2007 年資料の例に gain 0.001 → `3A83126F` がある（資料の例であり、受理実験ではない）
- 実データの計算チャネルには 16 桁（float64）の gain・offset がある（例 `3FF0000000000000`。F5 `[35B]` Longitude）[実測]。書き出し側は float32 だけで、float64 の gain を書く経路は無く [未確認]（ハブ §3 の読み取りの穴と対応）
- 位置の倍率: 名目 1e-7 を float32 にした実値 `33D6BF95`（`gps_entries.py:32`）。名目値で符号化して float32 の gain で読むと最大 1.6e-6 度ずれるため、符号化にも float32 の実値を使う（同 :1-12 のコメント。2D のロガーの倍率も `33D6BF95` で F5 の Lat_dez・Lon_dez と一致 [実測]）
- レート: レート＝基準 Hz÷除数。全チャネルのレートが基準 Hz の約数になること。RCZ2MES は基準 400 Hz 固定、レート候補は 400 の約数のうち 1〜100 Hz（`rcz_timeline.py:25,35`）。LD2MES の基準候補は 400・800・1000・2000（`ddd_generator.py:77`、LD2MES 版も同一）。400 は RCZ2MES の MES で Analyzer 受理 [受理]（`rcz_timeline.py:25` のコメントは「受理実績がある唯一の値」）。800 は 2023/2025 の実走ログ（2D 純正の記録）での受理実績とコメントにある（`ddd_generator.py:78`）が、変換ソフトが 800 で書いた MES の受理記録は確認できず [未確認]。1000・2000 は未検証
- 16 bit 整数の量子化: 値の最小〜最大を 0〜65535 に写す gain＝(hi−lo)/65535、offset＝lo。定数チャネルは gain 1・offset＝定数値（`ddd_generator.py:295-328`）[受理]。gain が 0 以下・非有限・float32 で 0 になる場合は書く前に拒否（`:373-382`）。書き出しは `round((物理値−offset)/gain)` を型の範囲へ clip（`mes_writer.py:293-318`）
- 符号付き 16 bit・符号付き 32 bit の書き出し経路は無い。位置の 32 bit も符号なし `<u4` で書き、負値は 0 に切り上がるため例外で止める（`gps_entries.py:37-58`）。ゆえに南緯・西経は書けない（RCZ2MES 台帳 B1）[推定: コード上そう読める]
- 名前: `,` `"` と制御文字（0x00-0x1F・0x7F）は `_` に置換、cp1252 で書けない文字は名前を落とす／単位だけ空にする（`ddd_generator.py:106-133,503-531`）。名前の一意化は 32 文字で切って衝突したら末尾に `_` を重ねる（`:258-292`）。32 は DDD の名前欄の長さとのコメント [推定]
- 不変量チェック（自ツール出力専用・`ddd_invariants.py:66-176`）: 1= 第1 が `4` と一致（かつ 10000 未満）／拡張子が `A[0-9A-Z]{2}` で一意かつファイルが実在／名前が一意／通し番号が 1..N／節 ID が一意（16 進正規化後も）。Analyzer が解釈する保証ではない（同 :1-12）

## 3. 生データファイル（A??・C??）

- ファイル名は `<MES名>.<拡張子>`（拡張子は DDD の `6=` 第4）。ヘッダ無し・リトルエンディアンの配列。チャネル情報は無い（ハブ §2、2007 年資料 §2）[実測]
- 型は `6=` 第1（バイト幅）と第2（型文字）で決まる。実装の写像: F は幅 32 以上で f4、64 以上で f8、その他 f2。W・I は幅 64 以上で u8、32 以上で u4、その他 u2（`ddd_generator.py:331-345`）。2007 年資料の「W＝符号なし 2 byte」とは、実データの Lat_dez（W で `6=` 第1 `FFFFFFFC`＝4 byte 幅）が合わない（part2 §9）
- サンプル数: 全チャネルを「基準 t0 から同じ時間長」にそろえる。RCZ2MES は n＝ceil(T×レート/1000)、T＝全機器で最初の時刻から最後の時刻まで（`rcz_timeline.py:80-92`）。LD2MES は round(レート×時間長)（`mes_writer.py:48-57`）。短いチャネルは Analyzer がエラーなしで黙って捨てる（V_Sat 消失として 2026-09-04 に実機で確認と同ファイルのコメント。当時の報告 `HA22S_M130_hed_format_decode.md` §5.2 は原因未解明）[実測のうえ後日の解釈]
- 記録の終わりまで続くか: SWO-V4 は Overview の線が 427.9 秒の終わりまで続き、全チャネルの標本が終わりまである（10 Hz で 4280 個＝428.0 秒）（M1 確認 5-1、指揮役が起動して確認）[受理]
- 時間軸: 時刻チャネルは無い。t＝標本番号÷レート、記録開始が 0（ハブ §2）。機器ごとに別時刻の元データは、共通 t0 へ線形補間でそろえる。標本間が 1050 ms を超える空きは補間せず直前の値を保つ（`rcz_timeline.py:27-29`、仮置き）。補間しない設計は、MES の 16 bit に「値なし」が無いため（設計書 `RCZ2MES_001_design.md` 85 行の記述）
- 欠測の表現: MES 側に「値なし」の決まりは確認できていない [未確認]。全標本が値なしのチャネルは書かない（RCZ2MES 設計）

## 4. HED（ヘッダ INI）

- 実体は cp1252・CRLF の INI。`[DOWNLOAD]`・`[GPS]`・`[Laptimes]`・`[SectionTimes]`・`[CalcTool]`・`[COMMENT]` など。チャネル定義・レート・gain・offset は一切持たない [実測]（`HA22S_M130_hed_format_decode.md` §1.1〜1.2）
- 無くても開ける。Analyzer は無い HED を `[Laptimes]` だけ（46〜47 byte）で作る [実測]（f6 調査 S2、実在 MES 54 件）。LD2MES はこの形で運用 [受理]
- 既存の HED は壊されない。Analyzer は `[Laptimes]` を足し、書かれていた `[DOWNLOAD]`（6 行）をそのまま残した [受理]（RCZ2MES M2 確認 #2）。2D 純正 Demo-CAR.HED も内容保持で mtime だけ更新 [実測]
- RCZ2MES が書く `[DOWNLOAD]`（`hed_download.py:24-26,47-63`、キー名と日付の形は F4 実物 HED から写した）: `Date=YY.MMDD`・`Time=HHMMSS`・`Timezone=+09:00`・`Start of download=DD.MM.YYYY HH:MM:SS`・`End of download=`（同じ値）・`MainSamplingRate=<基準Hz>`。日時は記録の最初の時刻（UTC）を秒で切り捨て、固定 +09:00 を足す。Analyzer の「いつも日付を見る場所」に正しく出た（2026-07-22 21:21:13）[受理]（M3a 確認 3-2、らいおが確認）
- `MainSamplingRate`: IXR の標本番号を何 Hz で数えるかを決めるらしい（`hed_download.py` の docstring）[推定]。実データの HED での位置は Mileage calculated の後。書かずに IXR だけ置いた場合は [未確認]
- 書かなかった欄: LapMeter・Run total・Loggername・Logger serial など。値の意味を変換側で決められないため。無くても受理 [受理]。`[DOWNLOAD] LapMeter [m]=0` 等の意味は [未確認]（ハブ §5）
- `[GPS]` 節は part2 §7。`[Laptimes]`・`[SectionTimes]` は Analyzer が書く欄で、変換側が書く必要はない [受理]（M3a で #1・#3 の区間時間を Analyzer が書いた）
- 実名: 実データの HED の `[INFO_2D]`・`[CalcTool]` には PC 名・Windows ユーザー名・ライセンス名義が平文で入る。外部共有する MES は HED を確認する [実測]（同 §1.1）
